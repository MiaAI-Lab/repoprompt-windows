Why This Exists

You don't need this tool. Until you do.

Letting an agent explore freely works great — until it doesn't. Curated context is the difference between "close enough" and "exactly right."

01

The "Just Use Claude Code" Argument

It's totally fair. You open your terminal, type claude or codex, and you're off to the races. The agent can read files, search your codebase, understand your project. So why would you spend time curating context by hand?

The answer is: you don't need this for quick edits or single-file changes. That's not what this is for.

But here's the thing about letting an agent explore on its own — it fumbles.

02

The Fumbling Problem

When an agent doesn't know your codebase, it does what any human would do: it starts poking around. ls here, grep there, read a few files, skip a few others. Every one of those operations burns tokens.

More importantly, the agent doesn't know what it doesn't know. There's a critical function in a file three directories deep that it never thought to look at. So it rewrites it. Now you have two implementations of the same thing. That happens all the time.

"If Claude is just reading around and never actually hits that function, it won't know it exists and it might recreate it — and you end up with a duplicate function."

With curated context, you decide what the agent sees. That function in the third directory? You hand-picked it. The agent starts with everything it needs. No fumbling. No duplicates. No tokens wasted on exploration.

03

The Anatomy of a Good Prompt

A well-structured prompt isn't just "write code that does X." It's a complete information package. Here's what goes into one:

📁 File Tree

A token-efficient map of your entire project. The agent understands at a glance what framework you're using, where configs live, and what's relevant — without needing to ls -R everything.

📄 File Contents

The full content of every file you selected. No gaps, no blind spots. If the function exists, the agent sees it. No more "I didn't know that file was there."

🔍 Code Maps

Extracted signatures of functions and classes. The agent learns how that auth service works without reading all 500 lines. It just needs the method signatures and types.

📋 Git Diff

What changed, filtered to just the files you're working on. Perfect for code review or understanding recent changes without dumping the entire diff.

All of this together means you can write a vague task like "fix the authentication logic" and the model knows exactly what you mean — because you've already given it the OAuth service code map, the routes file, and the database schema.

04

Letting an Agent In vs. Curating Context

Here's what you gain by spending 30 seconds curating files instead of letting the agent roam free:

Agent Roams Free

  • Burns tokens on ls and grep
  • May never find the key file
  • Recreates existing functions
  • Context fills up with irrelevant exploration
  • Can't reason across repo boundaries
  • No visibility into what it's "thinking" about

You Curate the Context

  • Zero token waste on exploration
  • Every relevant file is upfront
  • No duplicate implementations
  • The agent starts working immediately
  • Multi-repo context in one shot
  • You reviewed exactly what was sent
05

The Handoff Pattern

Here's where it gets interesting. You can use a discovery workflow: one agent explores your codebase, finds the relevant files, and writes a clear handoff prompt. Then a second agent — maybe a cheaper model — implements the work using that prompt.

"All of a sudden I've got a task that is much clearer to an AI model reading it. It knows about all of these files. It has a directory structure included. It didn't have to search for them."

This pattern is powerful because it creates a review checkpoint. The discovery agent hands you a plan. You read it. You tweak it. You approve it. Then the implementation agent starts working. You stay in control without doing the grunt work.

06

What This Means For You

The honest truth is that the engineer's job is shifting. It's becoming less about writing every line from scratch and more about organizing context — deciding what the AI should see, in what order, and with what instructions.

Tools like Codex CLI and Claude Code are amazing for quick, self-contained tasks. But when you're doing complex multi-file work, when you're reviewing a PR, when you're onboarding someone to a monorepo, or when you're trying to squeeze the best result out of a limited context window — that's when curated context earns its keep.

You don't need this tool for everything. But when you need it, you'll be glad it's there.
